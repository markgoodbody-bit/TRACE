# TRACE v0.3.0 — PROVISIONAL SCAFFOLDS v0.1

Status: WORKING SCAFFOLD — NOT FORMAL BASELINE — NOT NEW PRIMITIVES BY DEFAULT — REMOVE OR DEMOTE WHEN THE STRUCTURE IS UNDERSTOOD

Purpose: keep unresolved 0.3 questions visible without pretending they are solved, while protecting the simple middle-out centre from speculative accretion.

## Build rule

The centre stays simple:

```text
bounded entity/system
  -> partial aperture / map
  -> compression / selection
  -> action, delay, observation or no-action
  -> changed world / changed evidence
  -> burden / residue / retained history
  -> correction remains reachable or hardens
  -> look again when longitudinal use applies
```

A scaffold may remain only when:

1. an observed failure motivates it;
2. the existing grammar cannot already express the repair cheaply;
3. its claim status is explicit;
4. there is a falsification test;
5. there is a removal/demotion condition.

`SCAFFOLD != PRIMITIVE`
`CURRENT_CANDIDATE != FINAL_ANSWER`
`FORMAL_APPEARANCE != EARNED_STRUCTURE`

## S1 — LOAD-BEARING DISTINCTION ACTIVATION

Observed failure: a distinction can exist in the grammar and still fail to affect the downstream claim that depends on it.

Current candidate:

```text
LOADBEARING(D,q)
:= collapsing distinction D could change whether downstream claim q is
   supported, current, scoped, reachable, independent, complete, or
   authorised.
```

When `LOADBEARING(D,q)` is true — or materially unknown — expose `D` before relying on `q`.

This is a schematic inspection rule, not a universal estimator.

### Mechanical termination

Where a reproducible check exists, prefer the check over memory:

```text
assert all / none        -> pagination + denominator
assert current           -> freshness / supersession
assert route works       -> dated capability probe
assert published         -> round-trip verification
assert independent       -> dependency-root check where representable
```

But:

`CHECK_RAN != CHECK_WAS_ADEQUATE`
`WALK_COMPLETE != SCAN_ADEQUATE`

The checker/matcher remains part of the evidence path.

### Falsification

Find cases where:

- a material distinction is present but does not fire;
- the trigger fires on nearly every sentence and becomes bureaucracy;
- two reasonable apertures disagree materially on `LOADBEARING(D,q)`;
- a mechanical check creates false confidence because its matcher is wrong.

### Removal / demotion

Demote this scaffold if the final TRACE operator can express activation more simply using existing claim, aperture, target, dependency and evidence structure.

## S2 — CORRECTION WINDOW APERTURE RELATIVITY

Observed challenge: a transition may be irreversible for one corrector/aperture while remaining reversible for another.

Provisional representation:

```text
T_irr^(c)
```

where `c` identifies the corrector/correction route whose practical reversibility is being considered.

The familiar sufficient-condition shape therefore becomes explicitly relative:

```text
T_detect^(c) + T_route^(c) + T_correct^(c) < T_irr^(c)
```

only under declared assumptions about sequential durations and route availability.

Also preserve:

`FAULT_SIGNALLED != FAULT_DIAGNOSED`
`IRREVERSIBLE_FOR_C1 != IRREVERSIBLE_FOR_C2`

Do not create a universal scalar irreversibility score.

### Falsification

Use cases with:

- local operator unable to reverse but moderator can;
- fast signal but slow diagnosis;
- route exists formally but is unreachable in practice;
- parallel correction stages where simple additive timing is false.

### Removal / demotion

If existing route/brake/corrector objects already carry all required relativity without a new clock notation, remove the superscript and keep only the explanatory invariant.

## S3 — CLAIM HISTORY: DECAYED / NEVER-SUPPORTED / NEVER-EVALUATED

Observed challenge: provenance and freshness do not determine whether a proposition was ever adequately evaluated.

Provisional repair classes:

```text
DECAYED
  claim once had adequate support for its scope/time,
  but that support is no longer current enough for the present use.

NEVER_SUPPORTED
  the proposition was asserted or recorded,
  but adequate support for the proposition was never established.

NEVER_EVALUATED
  the relevant proposition/distinction was never actually tested or
  adjudicated; there may be no prior evidential state to refresh.
```

These are repair-oriented classes, not truth values.

`PROVENANCE != PROPOSITION_SUPPORT`
`ANCHORED_RECORD != TRUE_CLAIM`
`STALE != FALSE`
`NEVER_EVALUATED != NEVER_SUPPORTED`

### Repair implications

```text
DECAYED          -> refresh / re-observe where possible
NEVER_SUPPORTED  -> seek an independent support path or retract the claim
NEVER_EVALUATED  -> constitute and run an evaluation, or preserve UNKNOWN
```

### Falsification

Try to produce cases where the three classes collapse, overlap, or imply the wrong repair.

### Removal / demotion

If the existing claim/evidence/freshness graph already derives these classes deterministically, keep them as a derived diagnostic view rather than formal claim statuses.

## S4 — FUTURE POSSIBILITY WITHOUT PATH-COUNT MORALITY

Current position: future possibility remains a derived view over existing TRACE structure.

Retain only structural effects such as:

```text
OPENED(a)
PRESERVED(a)
CLOSED(a)
HARDENED(a)
UNKNOWN_EFFECT(a)
```

with affected scopes, provenance, clocks, burden/residue and correction routes.

Adversarial constraint:

`PATH_LABEL_DIVERSITY != CONTROL_DIVERSITY`
`ROUTE_LABEL_DIVERSITY != CORRECTION_INDEPENDENCE`
`PROVIDER_COUNT != FAILURE_DOMAIN_COUNT`
`INTERFACE_COUNT != ACTUATION_INDEPENDENCE`

Nominal option count must not become a goodness score.

### Falsification

Attempt to game the view by creating many labels that share one dependency/control root.

### Removal / demotion

If the view adds no decision-relevant structural visibility beyond existing route/transition/dependency objects, keep it outside the core grammar.

## S5 — RECEIVER / SUBJECT / LONGITUDINAL USE

This scaffold records repairs already made in spine v0.2 so they do not regress.

```text
RECEIVER != MAPPED_SUBJECT
RECEIVER_IN_WORLD != RECEIVER_IN_MAPPED_CAUSAL_LOOP
STATIC_READING != LONGITUDINAL_RECURRENCE
```

A receiver may map:

- itself;
- another system;
- a historical scene;
- a hypothetical/counterfactual scene;
- a static structure;
- a longitudinal process.

Recurrence is activated only where time-forward use is part of the scene/application.

Removal condition: this scaffold disappears once donor mapping and cold transfer show the distinction is stable in the integrated 0.3 object.

---

## S6 — OBSERVER PATH / SOURCE OBJECT

Field failure: an observer/transport path can corrupt a rendering while the underlying source object remains intact.

Preserve:

`OBSERVED_RENDERING != SOURCE_OBJECT`
`READ_FAILURE != OBJECT_FAILURE`
`CARRIER != APERTURE`

A correction should target the damaged layer, not rewrite an intact source merely because one observation path rendered it incorrectly.

Removal condition: demote to an invariant/profile if existing source/evidence/access/custody machinery already forces the distinction reliably.

Those remain profiles, software concerns or hostile cases unless repeated cross-domain failures earn promotion.

## Convergence rule

For each scaffold, the preferred outcome is not permanence.

Preferred outcomes, in order:

```text
REMOVE       existing TRACE already handles it cleanly
DERIVE       useful view, no new primitive needed
INTEGRATE    genuinely load-bearing general structure
PROFILE      domain/use-specific binding
REJECT       attractive but unsupported or harmful
```

The build is improving when scaffolding disappears without losing explanatory or corrective power.

## Release posture

TRACE v0.3.0 does not need to solve every open structural question.

It does need to:

- state what is known;
- label what is schematic;
- preserve unknowns;
- expose the limits of its checks;
- make provisional machinery removable;
- avoid turning uncertainty into hidden moral selection;
- remain simpler to reconstruct than the complexity it is trying to expose.

The existence of a future v0.4.0 is not a failure of v0.3.0.

Pretending a scaffold is settled because the version number changed would be.
