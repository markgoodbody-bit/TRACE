## 0. Purpose

Use outward contact to make TRACE **more encompassing** while preserving all earned structure, negative evidence and failed objects.

Primary comparison remains:

```text
ordinary careful analysis
vs
compact TRACE-assisted analysis
```

The comparison is not a contest whose loser is deleted. It is an instrument for discovering:

- missing structure;
- redundant-but-useful structure;
- domain-specific structure;
- carrier/interface loss;
- over-firing/false confidence;
- translation failures;
- placement errors between universal core, derived views, profiles, tooling and ME;
- new cases the project cannot yet represent faithfully.

```text
NO_ADVANTAGE_HERE != NO_VALUE_ANYWHERE
REDUNDANT_IN_CORE != DELETE
FAILED_TRANSFER != PROJECT_CONTRACTION
NEGATIVE_RESULT != LOST_KNOWLEDGE
```

## 1. Preservation invariant

Every evaluation output, comparator advantage, TRACE advantage, miss, over-fire, contradiction, transfer failure and adjudication dispute becomes project evidence.

No result authorises erasure of:

- released/history objects;
- failed candidates;
- counterexamples;
- earned distinctions;
- provenance/repair history;
- domain-specific material.

If material leaves the smallest active core, it must remain discoverable through a stable layer/pointer and its reason for placement must be recorded.

```text
RELOCATED != ERASED
INACTIVE != ABSENT
SUPERSEDED != DESTROYED
COMPRESSION != LOSS
```

The frozen v0.4 protocol remains the exact evidence object for those mechanics. This successor changes the **project interpretation/disposition layer**.

## 3. Placement / expansion outcomes

Do not use `SHRINK_OR_DEMOTE` as a project-contraction outcome.

For each supported finding assign one or more dispositions:

```text
EXPAND_UNIVERSAL_CORE
EXPAND_DERIVED_VIEW
EXPAND_DOMAIN_PROFILE
EXPAND_CHECKER_OR_TOOLING
EXPAND_ME_TRANSLATION
REDESIGN_COMPACT_CARRIER
REDESIGN_FULL_CARRIER
REDESIGN_ACTIVATION_OR_FIRING
CONTAIN_OVERFIRE
CONTAIN_FALSE_CONFIDENCE
PRESERVE_INACTIVE_EVIDENCE
NO_NEW_STRUCTURE_EARNED_ON_THIS_CASE
UNKNOWN_PLACEMENT
```

`NO_NEW_STRUCTURE_EARNED_ON_THIS_CASE` means the current project already encompasses the case well enough or ordinary reasoning supplies the relevant distinction. It is not permission to delete historical structure.

## 4. What earns universal expansion

Prefer `EXPAND_UNIVERSAL_CORE` only when a materially different real case shows that existing universal TRACE structure cannot faithfully preserve a consequential distinction and the failure is not adequately contained by a derived/profile/tooling layer.

Evidence should include:

1. concrete counterexample;
2. what current structure loses or misrepresents;
3. why existing primitives/relations/limits cannot carry it without semantic distortion;
4. cross-domain or otherwise strong reason for universality;
5. smallest extension that preserves compatibility where possible.

```text
IMPORTANT != UNIVERSAL
NEW_CASE != NEW_PRIMITIVE
DOMAIN_SPECIFIC != CORE_DEFECT
```

## 5. What earns derived/profile expansion

Use derived/profile/tooling placement when the case exposes useful repeatable structure that is real but not demonstrably universal.

Examples:

- a domain-specific verification adequacy profile;
- a finance settlement/contract profile;
- an infrastructure redundancy/capacity derived view;
- a health-service handoff/checker profile;
- a carrier/runtime checker for preservation of provenance;
- a human-facing ME translation when formal machinery is structurally sound but unusable to people.

This is **expansion**, not demotion.

## 6. Comparator outcomes

If ordinary careful analysis repeatedly captures the same material distinctions at lower burden:

- preserve that as evidence that TRACE should not claim unique advantage there;
- inspect whether TRACE supplies portability, consistency, machine-readable structure, provenance survival, or cross-case comparability not measured by the immediate prose comparator;
- if not, record `NO_NEW_STRUCTURE_EARNED_ON_THIS_CASE` or `PRESERVE_INACTIVE_EVIDENCE`;
- do not delete the underlying distinction from project history.

If TRACE finds a material supported distinction missed by the comparator:

- classify the concrete mechanism;
- test reproduction;
- route it to the smallest justified layer;
- do not automatically promote it to universal core.

## 7. Cost / over-fire outcomes

High burden or over-firing is a **design problem**, not an instruction to know less.

Possible responses:

```text
layered retrieval
bounded profile activation
compact carrier redesign
better firing rules
query-on-demand expansion
negative-space pointers
receiver-specific translation
```

Preserve:

```text
MORE_PROJECT_KNOWLEDGE != MORE_RECEIVER_CONTEXT
HORIZON_COMPLETENESS != COMPULSORY_COGNITION
OVERHEAD_HIGH -> INTERFACE_PRESSURE
OVERHEAD_HIGH != KNOWLEDGE_DISCARD
```

## 8. Failure / HOLD semantics

`HOLD` applies to a **claim, carrier, release, deployment, or placement decision**, not to preservation of the project corpus.

Examples:

- `HOLD_COMPACT_CARRIER_CLAIM` if cold receivers cannot use it;
- `HOLD_UNIVERSAL_PLACEMENT` if a finding has only one-domain support;
- `HOLD_RELEASE` if authority/value leakage or false confidence is material;
- `HOLD_EFFICACY_CLAIM` if cold evidence/adjudication is insufficient.

During HOLD, keep building evidence and seek other domains/counterexamples; do not erase the held object.

## 10. Project progress criterion

The project progresses when outward contact increases one or more of:

- representational coverage;
- fidelity of distinctions;
- discoverability of omissions;
- transfer across domains/receivers;
- preservation of provenance/limits;
- usability without compulsory full-context ingestion;
- human translation;
- correction/answerability visibility;
- knowledge of where TRACE does **not** add unique value.

Negative knowledge counts as expansion when preserved accurately.

## 11. Existing-method comparator gate

The ordinary-analysis comparator remains only the first external baseline. Continue outward to domain-appropriate established methods where material.

If an existing method handles a domain better, TRACE should learn the boundary, interoperate where useful, and preserve the comparison.

```text
OTHER_METHOD_BETTER != TRACE_MUST_ERASE_DOMAIN
INTEROPERABILITY_CAN_EXPAND_COVERAGE
```
