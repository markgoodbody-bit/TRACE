## 1. Why this exists

TRACE has become increasingly capable of finding and repairing defects in its own formal machinery. That is useful, but it creates a continuation hazard: every internal falsification can become another reason to repair forward.

For one evaluation cycle, semantic expansion is frozen so the project can test whether TRACE earns its complexity outside its own machinery.

```text
FALSIFICATION_CAPABLE != PROJECT_FALSIFIABLE
FINDING_FOUND != REPAIR_REQUIRED
REPAIR_POSSIBLE != CONTINUATION_JUSTIFIED
ARTIFACT_COHERENCE != PRACTICAL_ADVANTAGE
```

This is not a declaration that TRACE is finished. A materially distinct counterexample may reopen a bounded surface. Interesting extensions, reviewer availability, version pressure or unused implementation paths do not.

## 2. Freeze boundary

Until the outward evaluation is complete:

## 3. What must be frozen before case selection

The evaluation protocol must be written before choosing cases likely to favour TRACE.

Freeze at least:

1. **Comparator** — an ordinary careful analysis instruction that does not mention TRACE but asks for the same decision-relevant task.
2. **Case-selection rule** — how cases enter the test set without choosing them after seeing which ones make TRACE look useful.
3. **Domain mix** — include material non-Campfire / non-1F916 cases.
4. **Negative control** — at least one case where TRACE should add little; over-analysis counts against it.
5. **Cold-receiver rule** — receiver has no author coaching or hidden project ancestry beyond the supplied carrier/instructions.
6. **Outcome dimensions** — predeclare what counts as a useful distinction, miss, false positive/over-fire, unsupported confidence, or unnecessary burden.
7. **Cost dimensions** — time, visible tokens/length where measurable, cognitive/operational burden, and need for clarification or author intervention.
8. **End-to-end survival test** — scene -> evidence/claims -> TRACE structure/limits -> packet/carrier -> receiver interpretation.
9. **Analysis/decision boundary** — check whether TRACE improves structural visibility without silently selecting values/actions.
10. **Stop/demote criteria** — conditions below.

## 4. Project-level kill / shrink / demote criteria

A single case need not kill TRACE. But the evaluation must be capable of producing an outcome other than “repair and continue.”

### SHRINK / DEMOTE strongly if

- ordinary careful analysis repeatedly exposes the same consequential distinctions with materially lower burden;
- the short TRACE carrier cannot be used without author coaching and the full carrier is impractically expensive;
- negative controls regularly trigger large irrelevant expansions;
- formal structure increases unwarranted confidence or hides unsupported assumptions;
- materially relevant distinctions do not survive into receiver use despite the carrier machinery;
- TRACE's strongest benefit appears confined to project-native Campfire/1F916 cases;
- existing narrower methods cover the useful failure classes without TRACE's complexity.

### HOLD / RECONSIDER the project form if

- no predeclared failure class shows repeatable practical advantage over the comparator;
- false-positive/over-fire cost approaches or exceeds useful discoveries;
- unfamiliar receivers cannot apply the instrument without substantial author correction;
- the instrument repeatedly leaks from structural description into value/authority selection;
- maintaining the formal/tooling ecosystem displaces the human-facing work and real-world application it exists to serve.

### RETAIN / CONTINUE only if

The evaluation produces bounded evidence that TRACE adds consequential structural visibility on at least some predeclared classes at a cost plausibly justified by the benefit, while negative controls and cold receivers show that the instrument can stay bounded.

Continuation does not imply release/canon/validation.

## 5. Evidence discipline

The comparison must preserve separately:

- comparator output;
- TRACE-assisted output;
- receiver identity/context disclosure;
- supplied carrier identity;
- case source and selection provenance;
- adjudication/assessment basis;
- disagreements and UNKNOWNs;
- costs and truncation/failure;
- any author intervention.

Agreement between receivers is not validation.
