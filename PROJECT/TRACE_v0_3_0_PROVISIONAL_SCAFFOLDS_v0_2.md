## 0. Build rule

The centre remains simple:

```text
bounded entity/system
  -> partial aperture / supplied material
  -> partial map / retained history
  -> alternatives / constraints / target apertures
  -> selection, action, delay, observation or null input
  -> changed world / changed evidence
  -> burden / residue / correction / hardening
  -> look again where longitudinal use applies
```

A scaffold remains only when:

1. an observed failure motivates it;
2. existing grammar cannot already express the repair cheaply enough;
3. its status is explicit;
4. it has a falsification target;
5. it has a removal/demotion condition.

```text
SCAFFOLD != PRIMITIVE
CURRENT_CANDIDATE != FINAL_ANSWER
FORMAL_APPEARANCE != EARNED_STRUCTURE
```

Preferred outcomes:

```text
REMOVE -> DERIVE -> INTEGRATE / PROFILE -> REJECT
```

where `INTEGRATE` is not automatically better than `DERIVE`.

# S1 — OPERATOR INTERFACES: INGRESS / ACTIVATION / CHECK

**Current exact object:** `TRACE_v0_3_0_OPERATOR_INTERFACES_CANDIDATE_v0_1.md`

Observed failures now separate into three locations:

```text
I  INGRESS / CONSTITUTION
   supplied material may become standing map / retained premise

X  ACTIVATION
   represented distinctions may remain dormant at downstream use

C  CHECK / ACTUATION
   a fired distinction may have no adequate executable/returned check
```

These are currently **derived operator interfaces**, not semantic roots.

Core boundaries:

```text
SIGNAL_RECEIVED != MAP_ADOPTED
TRIGGER_SUCCESS != REPRESENTATION_COMPLETE
CHECK_PATH_EXISTS != CHECK_EXECUTED
CHECK_EXECUTED != CHECK_WAS_ADEQUATE
```

The spine already contains the receiver-specific optional integration seam:

```text
M_receiver+ = J_receiver(M_receiver, R, L)
```

so ingress does not yet earn a primitive.

Activation is now anchored to a represented downstream use and its represented dependency slice, not to a self-declared narrow claim alone.

Check/actuation preserves proposition fit, coverage, instrument capability/resolution, evidence/control dependencies, timing and return route.

### Falsification

Break S1 by showing that:

- ingress discipline forces re-derivation of ordinary inherited knowledge;
- activation expands routine readings toward the full packet;
- a narrow represented use still launders a broader operative use;
- representation selection makes every later check internally clean while omitting the load-bearing world relation;
- a check is blind/precommitted but still useless because source or instrument is bad;
- the same effect already follows automatically from existing TRACE without an operator statement.

### Removal / demotion

Prefer **DERIVE**. Remove the named interfaces if ordinary use of existing `APERTURE / MAP / CLAIM / EVIDENCE / ROUTE / HISTORY / BOUNDS / OMITS / DISPUTES` machinery reliably produces the same corrections.

# S3 — CLAIM HISTORY / REPAIR CLASS

Current provisional repair-history classes:

```text
DECAYED
  adequate support existed for an earlier declared scope/time and lost currency

NEVER_SUPPORTED
  an assertion/record existed but adequate support for the proposition was never established

NEVER_EVALUATED
  the relevant proposition or distinction was never actually evaluated / adjudicated
```

These remain **repair/evaluation-history classifications, not truth values**.

```text
SOURCE_ANCHORED != PROPOSITION_SUPPORTED
HISTORICALLY_SUPPORTED != CURRENTLY_SUPPORTED
NEVER_EVALUATED != NEVER_SUPPORTED
```

Typical repair implications:

```text
DECAYED          -> refresh / re-observe / re-derive
NEVER_SUPPORTED  -> seek a different evidential route or narrow/retract
NEVER_EVALUATED  -> constitute an evaluation if possible, otherwise preserve UNKNOWN / retire unsupported projection
```

### Removal / demotion

If ordinary claim/evidence/freshness graphs deterministically derive these classes, keep them as a diagnostic view only.

# S6 — OBSERVER / REPRESENTATION PATH VS SOURCE OBJECT

Field failures established:

```text
OBSERVED_RENDERING != SOURCE_OBJECT
READ_FAILURE != OBJECT_FAILURE
CARRIER != APERTURE
POINTING_TO_SOURCE != PRESERVING_SOURCE_ACT_TYPE
```

A perfect-fidelity carrier can still preserve a semantic re-typing already introduced during representation. Therefore source pointers and byte fidelity are useful but not sufficient to prove representational adequacy.

Where a traversed dependency relies on excerpt/paraphrase/representation and the representation act itself is specifically capable of changing downstream use, keep that unresolved relation visible or reacquire the source through an alternate route.

### Removal / demotion

Prefer existing provenance/evidence/aperture structure. Keep only a profile/invariant if no new relation is required.

# S7 — REPRESENTED USE / OPERATIVE USE

This remains an **open attack surface**, not an earned primitive.

```text
REPRESENTED_USE != OPERATIVE_USE
```

A reader can otherwise frame a narrow use and starve activation of dependencies relevant to the actual selection or transition.

The candidate repair is bounded: preserve a use-completeness fork only where a **specific** broader operative use can be named that would change the activated dependency set.

```text
GENERIC_POSSIBLE_BROADER_USE != MATERIAL_OMISSION
```

### Removal / demotion

If target-set / downstream-selection structure already makes operative-use scope explicit enough, merge this into S1 and delete S7.
