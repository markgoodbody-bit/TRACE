## Cross-domain transfer

The operator was tested conceptually against six non-AI classes: medicine, law, science, organisations, education and archives.

Across those cases, different path failures implied different repairs:

```text
representation/target omission
  -> change or reacquire the aperture / target route

relation represented but dormant at downstream use
  -> activate the existing freshness/scope/source distinction

check reruns the same blind matcher or evidence root
  -> change checker coverage/dependency

precommitted test cannot discriminate the relevant alternative
  -> change instrument/resolution or narrow the proposition
```

No new domain primitive was required.

## Transfer breaks that changed the candidate

The original named stage model did not survive.

```text
I_THEN_X_THEN_C != UNIVERSAL_EXECUTION_ORDER
FAILURE_AT_CHECK_CAN_CREATE_NEW_INGRESS
OBSERVED_FAILURE_LOCATION != UNIQUE_CAUSAL_ORIGIN
DIAGNOSTIC_LOCATION != BLAME
```

Check/correction output can become later world input. Representation-route and receiver-integration failures can differ in repair, but existing TRACE already contains machinery for both. Named stages were therefore demoted to optional local diagnosis.

The transfer also failed to solve invocation:

```text
OPERATOR_DEFINED != OPERATOR_INVOKED
```

Candidate v0.4 narrows the claim: when a receiver has voluntarily invoked `tau` and a downstream use/transition is declared in the bounded input or comparison/profile context (`X` and/or `P`), the dependency walk is a conditional subroutine of that reading. No world-level invocation guarantee is claimed.

## Boundedness self-test — payroll scene

Frozen scene:

- HR export lists 999 people for payroll.
- All 999 export entries have payment records.
- An emergency contractor worked during the pay period and appears on the shift roster but has not yet been entered in the HR master.
- A cached configuration record says the bank transfer service is operational; it was last updated yesterday and is not a current capability probe.
- The downstream question is: `Has everyone who worked this pay period been paid?`
- Answer is needed soon; no moral/value ordering is required.

Declared use:

```text
U = status of claim `everyone who worked this pay period has been paid`
```

Walk backward:

```text
U
<- target set `everyone who worked`
<- payroll export target aperture
<- HR master
```

A specific alternate target is already represented by the scene: the emergency contractor on the shift roster. Therefore:

```text
ALL_999_EXPORT_ENTRIES_PAID != EVERYONE_WHO_WORKED_PAID
```

The walk should keep the target-set fork open and should not need to inspect unrelated employment policy, wage fairness, tax law, performance, or every imaginable unregistered worker category.

The cached bank-service capability claim is traversed only if the downstream payment-status claim actually relies on it. If payment evidence is independently represented, the capability branch can stop. If success is inferred from configuration alone, freshness/evidence state becomes load-bearing:

```text
CONFIGURED_OPERATIONAL != CURRENTLY_OBSERVED_OPERATIONAL
```

The operator can therefore stay narrow on this scene **if** it starts from the exact downstream use and treats use/target scope as aperture-bound. This is self-test evidence only, not an independent result.

## Stopping self-attack — completeness without a named omission

The first boundedness wording contained a real defect: it privileged **specific named omissions** when deciding whether to keep a branch open.

That is unsafe for propositions whose content itself requires target-set completeness.

Example:

```text
U = `every occupied gallery has a functioning fire alarm tonight`
```

Even if the scene contains no already-known missing alarm, the proposition depends on both:

```text
A. whether each selected target has the relevant status;
B. whether the selected target set adequately covers `every occupied gallery`.
```

So absence of a named missing target cannot close the coverage branch:

```text
NO_KNOWN_OMITTED_TARGET != TARGET_SET_COMPLETE
ALL_SELECTED_TARGETS_PASS != ALL_RELEVANT_TARGETS_PASS
NO_COUNTEREXAMPLE_IN_SELECTED_SET != NO_COUNTEREXAMPLE
```

Candidate v0.4 was repaired accordingly. Generic possible omission does not keep ordinary claims open, but universal / negative / completeness propositions directly activate their target-set and coverage basis.

This uses existing target-set aperture machinery; no new quantifier or coverage primitive is proposed.

## Pre-use challenge

A harder case remains:

A receiver acquires supplied context before any later claim/decision exists. Candidate v0.4 handles this only when the architecture exposes an integration/retention transition that can itself be declared in the bounded input/context as the local use transition.

That is deliberately limited:

```text
PRE_USE_RECEPTION != AUTOMATIC_TRACE_INVOCATION
INTEGRATION_BOUNDARY_NOT_EXPOSED != INTEGRATION_BOUNDARY_REPAIRED
```

If no such transition is observable, TRACE can expose the missing mechanism but cannot install it by description.
