# 3. Core/spine repairs earned by the field

These are the smallest changes that appear to belong in the eventual v0.3 core/spine rather than only in a profile or worked case.

## 3.1 Freshness must be invalidation-relative, not time-only

The #2101 case is stronger than ordinary `OLD_EVIDENCE != CURRENT_STATE`.

A derived value may carry a date that is still literally current while the source object has already changed several times inside that date bucket.

Preserve:

```text
DATE_CURRENT != DERIVED_VALUE_CURRENT
TIME_HORIZON != MUTATION_HORIZON
SOURCE_CHANGED_WITHIN_TIMESTAMP_BUCKET != TIMESTAMP_STALE
RECOMPUTABLE_DERIVATION != STORED_DERIVED_VALUE
CURRENT_AT_USE != VALID_THROUGH_DEPENDENT_INTERVAL
```

Where currentness is load-bearing, a reading should preserve the represented **invalidation basis** when known. Examples:

```text
time / age
source mutation
version change
new event
new measurement window
policy / grant change
capability change
route change
```

This does not require a new `FRESHNESS` primitive. Existing claim/evidence/record/clock/transition structure is sufficient.

A time-to-live is one possible invalidation policy, not the universal form of freshness.

```text
FRESHNESS_POLICY != TIME_TO_LIVE_ONLY
NO_TIME_EXPIRY != NO_INVALIDATING_EVENT
```

## 3.2 Measurement/publication may be an intervention

The #2096 census case shows that a measurement or publication can change the later scene it is intended to measure.

TRACE already has `MEASURE`, `ACTION`, `TRANSITION`, `CAUSES`, and `CONTRIBUTES_TO`. No new object is needed. The repair is to prevent `MEASURE` from being treated as implicitly passive.

Preserve:

```text
MEASUREMENT != PASSIVE_OBSERVATION
PUBLICATION_OF_MEASUREMENT != NONINTERVENTION
MEASURED_STATE_t+1 != COUNTERFACTUAL_UNMEASURED_STATE_t+1
REPEATED_CENSUS != REPEATED_MEASUREMENT_OF_SAME_PROCESS
```

Where a measurement, audit, publication, notification, or inquiry can itself alter the represented system, represent that act on the causal path.

This is conditional. Do not force every measurement into a causal intervention claim without evidence.

## 3.3 Instrument adequacy needs an operational discrimination boundary

#2099 sharpens Root C.

A check can exist, be documented, parse correctly, and look reasonable while still never having demonstrated that it can detect the failure relevant to the current proposition.

Preserve:

```text
CHECK_EXISTS != CHECK_DETECTS_TARGET_FAILURE
INSTRUMENT_REVIEWED != INSTRUMENT_EXERCISED
EXPECTED_FAILURE_PATH != OBSERVED_FAILURE_PATH
STATIC_CORRECTNESS != OPERATIONAL_DISCRIMINATION
```

This does not mean every check requires destructive live fault injection. It means that when instrument adequacy is load-bearing, the basis for believing the relevant alternative is detectable must remain visible.

Existing `CLAIM`, `EVIDENCE`, `MEASURE`, `VERIFIES`, dependency, and check-route structure is sufficient.

## 3.4 Silence/liveness does not license a causal diagnosis

#2138 and the local stale-worker case expose the same warrant problem at different scales.

A missing heartbeat, stale status, absent reply, or silent route can establish loss of current verification/liveness under a stated observation model. It does not by itself identify the cause.

Preserve:

```text
SILENCE != TAMPERING
NO_REPLY_OBSERVED != REFUSAL
PROCESS_EXISTS != PROCESS_HEALTHY
MUTEX_HELD != WORKER_HEALTHY
SAFE_EXCLUSION != LIVENESS
WITNESS_LIVENESS_LOST != CAUSE_ESTABLISHED
```

A bounded witness may legitimately close a verification interval:

```text
CURRENT_STATE_UNVERIFIED_AFTER_t
WITNESS_LIVENESS_LOST
```

Those are claim states/descriptions, not new node types and not proof of compromise.

## 3.5 External witness does not imply independent witness

#2093 and the broader epistemic-ancestry work reinforce an existing dependency problem.

Preserve:

```text
EXTERNAL != INDEPENDENT
WITNESS_OBSERVED_X != EVERY_READER_WAS_SERVED_X
HASH_MATCH != CONTINUOUS_CONTENT_IDENTITY
EXTERNAL_CLOCK != COMPLETE_OBSERVATION
SEPARATE_PARTY != INDEPENDENT_EVIDENCE
```

Witness topology belongs on the represented dependency/control path. A witness can establish what it observed without establishing that all observers received the same object or that its control root is independent.

No `WITNESS` primitive is required; existing aperture/entity/claim/record/dependency/control structure is sufficient.

## 3.6 Null/level result does not establish mechanism absence

The #2096 preregistration repair is a direct Root A case.

Preserve:

```text
NO_EFFECT_DETECTED != MECHANISM_ABSENT
NULL_RESULT != MECHANISM_ABSENT
RANDOMIZED != INFINITELY_POWERED
```

A result only licenses the proposition supported under the design, power, treatment definition, interference assumptions, and measurement limits actually represented.

No new statistical subsystem is required.

# 4. Correction-window integration blocker

The current spine's simple serial inequality is not sufficient as the final v0.3 representation.

Historical work has already shown:

```text
REQUIRED_CHECK_TIME != ZERO_DURATION
POINT_ESTIMATE_FITS != GUARANTEED_OPEN
OVERLAPPING_TIME_BOUNDS != WINDOW_FITS
TARGET_CLOSE_IS_NOT_AN_EVENT_WITHOUT_AN_ADEQUACY_THRESHOLD
BOUNDARY_CONDITION_DECLARED != BOUNDARY_CONDITION_PREDECLARED
UNREACHABLE_BY_DECLARED_ROUTE_SET != WORLD_IRREVERSIBLE
MULTIPLE_LOAD_BEARING_BOUNDARIES != ONE_UNQUALIFIED_CLOSE
CURRENT_AT_USE != VALID_THROUGH_DEPENDENT_INTERVAL
PATH_EVENT_CHANGES_TARGET_PROCESS != STATIC_BOUNDARY_TIME_STILL_VALID
```

Therefore the next integrated spine must not present

```text
T_detect + T_route + T_correct < T_irreversible
```

as the primary general correction-window object.

It may survive only as an explicitly bounded shorthand for one sequential, fixed-boundary case.

The minimum integration target is:

1. represent load-bearing correction work as an event/precedence graph when stages can overlap or branch;
2. compute completion from the represented critical path, including required verification/check work;
3. bind the target boundary to an explicit represented condition rather than assuming every target has a natural close instant;
4. preserve target effect/state, affected scope, selector/source/basis, and freeze time where outcome-informed threshold choice is possible;
5. preserve corrector/route-set/capability scope when `unattainable` or `restorable` is capability-relative;
6. use interval-safe timing when event/boundary times are uncertain;
7. keep multiple load-bearing boundaries explicit unless a declared composition rule is justified;
8. rebind the window claim when target, boundary condition, capability scope, or relevant process changes;
9. return `UNRESOLVED` rather than manufacture a boundary when the required target condition is absent.

This is still an attack target. It is not yet permission to merge the correction-window delta into the formal baseline.

```text
REPAIR_TARGET_SELECTED != REPAIR_SURVIVED
DONOR_RECOVERY != NEW_PRIMITIVE
```


But instrumentation belongs in the evidence/tool layer. Repeated instrument failures may earn guards in TRACE; they do not make the instruments part of TRACE.

# 8. What the next v0.3 integration candidate should change

Do not build a new version number yet.

The next coherent integration candidate should be a revision of the current v0.3 spine with a **small patch surface**:

### A. Claim/evidence/currentness

Add invalidation-relative freshness and dependent-interval validity without creating a new primitive.

### B. Selective causal loop / measure

State explicitly that observation/measurement/publication may itself be causal when represented evidence supports that path.

### C. Verification

Add operational discrimination and liveness ceilings:

```text
CHECK_EXISTS != CHECK_DETECTS_TARGET_FAILURE
INSTRUMENT_PRESENT != INSTRUMENT_ACTIVE
WITNESS_LIVENESS_LOST != CAUSE_ESTABLISHED
EXTERNAL != INDEPENDENT
```

### D. Correction window

Replace the current point/sequential presentation as the general form with the event/precedence + explicit target-boundary + interval-safe structure selected in section 4.

### E. Full-object donor restoration

After the spine is coherent, restore or explicitly reference donor capabilities that the shorter spine cannot silently delete, especially:

```text
primitive-set aperture
absence / stream / pattern
access / custody
nested boundaries
coupling / refusability detail
future-space comparison
clock typing / interval timing / overlapping DAG
record / custody
full designation / measure ports
recursive zoom
packet / validator ceiling
worked transfer regressions
```

This restoration should not automatically make the front-door object longer. Deep capability can remain in the full formal object while the teaching/front-door surface stays small.

# 9. Self-attack targets for this pass

Hold this integration selection if any of the following is demonstrated:

1. mutation-relative freshness is already fully represented and reliably invoked by existing v0.2.7/v0.3 text, making the proposed repair redundant;
2. treating measurement as potentially causal creates generic scepticism or forces ordinary measurement into unnecessary action modelling;
3. operational-discrimination language collapses `instrument can detect` into `fault injection was performed`;
4. liveness vocabulary silently becomes a new universal state taxonomy;
5. the correction-window integration target still hides moral adequacy inside target-boundary selection;
6. interval-safe timing produces false confidence when timing distributions/bounds are not supportable;
7. the dependency operator / cold-entry / checker surfaces are being smuggled into core through wording rather than explicit integration;
8. donor restoration recreates the full v0.2.7 carrier without earning a clearer v0.3 architecture;
9. one of today's field cases is being credited as independent evidence despite Framework/CC participation helping create the observation;
10. the pass changes labels without changing any available repair or refusal.

One material counterexample is enough to revise this object.
