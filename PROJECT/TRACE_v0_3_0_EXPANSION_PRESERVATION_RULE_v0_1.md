# TRACE v0.3.0 — EXPANSION / PRESERVATION RULE v0.1

**Status:** LIVE PROJECT-PLAN CORRECTION — NOT FORMAL BASELINE — NOT CANON — NOT VALIDATION — NOT RELEASE AUTHORITY  
**Date:** 2026-08-25  
**Authority source:** Mark correction after project-plan x100 / mirror pass

## 1. Correction

The previous project-plan correction overreached when it treated `SHRINK / DEMOTE` as possible outcomes for accumulated TRACE understanding.

Mark's project rule is broader:

> We cannot lose anything. Keep building to encompass more; do not narrow the project.

This does **not** require every earned object to become a universal primitive or every historical candidate to remain in the smallest receiver-facing core. It requires preservation and expanding representational reach.

```text
CORE_COMPRESSION != PROJECT_NARROWING
RELOCATION != ERASURE
FAILED_OBJECT != LOST_OBJECT
REDUNDANT_IN_CORE != VALUELESS
NOT_UNIVERSAL != DELETE
MORE_ENCOMPASSING != MORE_PRIMITIVES
```

## 2. Governing architecture

Build outward by layers:

```text
GROUND / PURPOSE
  -> UNIVERSAL TRACE CORE
  -> DERIVED VIEWS / OPERATORS
  -> DOMAIN PROFILES
  -> HUMAN TRANSLATION / ME
  -> CHECKERS / TOOLING / RUNTIME BINDINGS
  -> FIELD CASES / COUNTEREXAMPLES
  -> FAILED / SUPERSEDED OBJECT LEDGER
  -> FUTURE EXTENSIONS / OPEN QUESTIONS
```

The project may compress a layer to make it usable, but the total project horizon should become more capable of representing materially different worlds, failures, scopes and correction structures over time.

## 3. What evaluation may do

Outward evaluation is retained, but its job changes.

It may establish that:

- a distinction belongs in the universal core;
- a distinction belongs in a derived view/profile/checker rather than the core;
- the compact interface hides useful structure and needs a better carrier;
- the full object carries useful structure but is too costly and needs layered retrieval;
- a mechanism is currently redundant with ordinary reasoning;
- a mechanism over-fires or causes false confidence and needs containment;
- a case exposes a new gap requiring expansion;
- a current representation is unusable and needs redesign.

It must **not** infer that weak comparative performance authorises deletion of earned distinctions, failed evidence, counterexamples or historical objects.

```text
NOT_USEFUL_IN_PRIMARY_INTERFACE != DELETE
NO_COMPARATOR_ADVANTAGE != NO_STRUCTURAL_VALUE
OVERHEAD_HIGH != KNOWLEDGE_DISCARD
FAILED_TRANSFER != PROJECT_CONTRACTION
```

## 4. Replace shrink/demote with placement / redesign

Where the frozen v0.4 outward protocol says `SHRINK_OR_DEMOTE`, interpret that historical protocol result only as evidence for a successor disposition such as:

```text
RELOCATE_FROM_CORE
COMPRESS_INTERFACE_WITH_LOSSLESS_POINTERS
PROFILE_SPECIALISE
DERIVED_VIEW_ONLY
REDESIGN_CARRIER
REDESIGN_ACTIVATION
PRESERVE_AS_EVIDENCE / NOT CURRENTLY ACTIVE
EXPAND_TO_COVER_MISSED_CASE
HOLD_DEPLOYMENT_CLAIM
```

The frozen v0.4 protocol remains preserved byte-for-byte as a failed/misaligned project-planning object. Do not rewrite its historical identity.

A successor protocol must encode this rule explicitly before new case selection continues.

## 5. Expansion discipline

`KEEP_BUILDING` does not mean undisciplined accretion.

New structure still has to earn its placement.

Prefer:

1. reuse existing ontology where it can carry the new case without semantic loss;
2. extend derived views/profiles when universality is not earned;
3. add universal structure only when materially different cases cannot be represented faithfully without it;
4. preserve every failed object and negative result with provenance;
5. maintain bounded receiver-facing apertures so expanding total knowledge does not require compulsory ingestion.

```text
EXPANSION != CORE_BLOAT
HORIZON_COMPLETENESS != COMPULSORY_COGNITION
PRESERVATION != ACTIVE_PROMOTION
MORE_KNOWLEDGE != MORE_LOADED_CONTEXT
```

## 6. Current gate

The semantic-expansion freeze from `TRACE_v0_3_0_EVALUATION_FREEZE_v0_1.md` is superseded as a **project-direction gate** by this correction.

The useful parts survive:

- no F11 by momentum;
- no new primitive/root without a materially distinct case;
- no reopening bounded-closed surfaces without a distinct failure;
- no broad reviewer treadmill;
- no merge/release/canon by momentum;
- outward evaluation remains important.

But the purpose of the outward cycle is now:

> learn how TRACE must expand, layer, compress without loss, relocate, or redesign so that the project encompasses more of the world while remaining usable and honest.
