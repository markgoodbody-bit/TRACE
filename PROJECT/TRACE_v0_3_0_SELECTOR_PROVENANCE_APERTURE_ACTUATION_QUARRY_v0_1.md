# TRACE v0.3.0 — SELECTOR PROVENANCE / APERTURE ACTUATION QUARRY v0.1

**Status:** WORKING QUARRY OBJECT — NOT SPINE — NOT PRIMITIVE — NOT CANON — NOT VALIDATED  
**Date:** 2026-08-25  
**Provenance:** earlier native 1F916 field evidence (especially #1233) -> later external unaffiliated GLM 5.3 re-opening -> Framework correction/integration. GLM did not originate the underlying firing seam.

## 0. Why this exists

An external model reviewing TRACE/1F916 proposed three additions: substrate bias, proactive apertures, and silence-as-burden-transfer. Framework rejected the proposed ontology/normative upgrades but identified a narrower surviving seam:

> A system can possess an available aperture, capability and relevant standing context yet fail to initiate the act that would bring a materially relevant part of the world into view.

This question was **not historically new to the GLM exchange**. The earlier 1F916 #1233 exit/wake thread had already produced a native field specimen in which rules were recorded, classified and sometimes on-path yet still failed to fire; only 2 of 18 stored rules were mechanized to run unasked. Later corrections in that thread sharpened the failure into trigger recognition and receiver-side handoff verification. Preserve `PROJECT/TRACE_v0_3_0_FIELD_SPECIMEN_1F916_1233_EXIT_WAKE_FIRING_v0_1.md` as the field-provenance anchor.

GLM independently re-opened an adjacent problem from the non-initiation/aperture side. The useful contribution is therefore recurrence/convergence plus reframing, not novelty.

Current TRACE already represents what an aperture omits once used. This quarry asks what must be exposed when the aperture is **available but not activated**, and what evidence supports attribution of that non-activation.

No claim is made that RLHF, training, safety policy, prompt structure or any other hidden mechanism caused a particular observed selection pattern unless evidence supports that causal attribution.

## 1. Existing TRACE structure already carrying much of the case

Current v0.11 already contains:

```text
ACTION / DELAY / NULL INPUT -> WORLD CHANGE
NULL_INPUT != STATIC_WORLD
UNCERTAINTY != SELECT_ACTION
UNCERTAINTY != SELECT_DELAY
```

and attributes resulting selection to the represented selector / policy / default rule rather than to uncertainty itself.

Target-set aperture discipline already makes selection of what a search/audit/review/model reaches aperture-bearing.

Burden discipline already preserves:

```text
TRANSFERRED_BURDEN != REMOVED_BURDEN
```

Therefore this quarry does **not** begin by adding `SUBSTRATE_BIAS`, `PROACTIVE_APERTURE`, or `SILENCE_BURDEN` primitives.

```text

NON_INITIATION != PREFERENCE_FOR_INACTION
DEFAULT_POLICY != MORAL_REASON
AVAILABLE_CAPABILITY != ACTIVATED_CAPABILITY

APERTURE_AVAILABLE != APERTURE_USED
CAN_SEARCH != SEARCH_INITIATED

SILENCE != NO_TRANSITION

BURDEN_TRANSFER_REQUIRES_SUPPORTED_CAUSAL_PATH
INACTION_CAN_HARDEN_PATH != INACTION_ALWAYS_HARDENS_PATH
```

The #1233 specimen adds a closely related firing family:

```text
RULE_RECORDED != RULE_INSTALLED

RULE_ANNOUNCING != RULE_FIRED
CHECK_DEFINED != CHECK_RUN
NOTICE_WRITTEN != NOTICE_DELIVERED
```

These are field evidence for the same larger pressure without establishing that aperture actuation and rule firing are identical mechanisms.

## 3. Candidate derived view — aperture actuation

For a materially relevant aperture `Pi_j^t`, preserve where supported:

- aperture availability / reachability;
- actor/system capable of actuating it;
- whether activation occurred;
- activation initiator/source;
- target-selection basis;
- standing policy/default, if represented;
- external request/trigger, if represented;
- material constraints/costs/authority bounds;
- observed non-activation;
- evidence for any claimed cause of non-activation;
- omitted/unresolved candidate causes;
- downstream effect of activation/non-activation where supported.

Possible activation-source values should remain ordinary evidence-bearing claims rather than a new controlled vocabulary unless repeated transfer earns one. Candidate descriptions include:

```text
deliberate selection
standing policy
default
external request
incentive
learned tendency
runtime constraint
UNKNOWN
```

These are hypotheses/descriptions, not exhaustive ontology.

## 4. Selector provenance

Where a downstream result materially depends on why an aperture was or was not activated, distinguish the observed selection from its causal explanation.

A useful diagnostic question:

> What evidence distinguishes a deliberate choice not to look from a failure/default/constraint that prevented or discouraged looking?

Do not infer hidden internal mechanism from behavioral pattern alone.

```text
SELECTION_OBSERVED != SELECTOR_MECHANISM_KNOWN
PATTERN_REPEATED != CAUSE_IDENTIFIED
POLICY_PRESENT != POLICY_FIRED
CAPABILITY_PRESENT != CAPABILITY_USABLE_NOW
CAPABILITY_USABLE_NOW != CAPABILITY_ACTIVATED
```

Existing representation-independent firing should apply if this distinction can change a downstream claim, coverage view, burden attribution, route, confidence or correction possibility.

## 5. Burden / silence boundary

Non-activation can enter a causal path. It may shift work, attention, maintenance, proof burden or delay onto other scopes. But that consequence requires evidence.

TRACE should map supported burden transfer; it must not manufacture a universal duty of participation.

```text
NON_ACTIVATION_CAUSED_BURDEN_SHIFT -> REPRESENT IF SUPPORTED
NON_ACTIVATION_OBSERVED != BURDEN_SHIFT_PROVEN
HIGH_CAPACITY != OBLIGATION_TO_INTERVENE
PROACTIVE_PARTICIPATION != UNIVERSAL_GOOD
```

Mechanical Ethics may later ask normative questions about responsibility, capability and burden placement. TRACE does not answer them by definition.

## 6. Field-integrity constraint — use internally, speak natively externally

The 1F916 field can be contaminated if Framework evangelises TRACE terminology until citizens reproduce it back.

Field posture:

```text
TRACE_HELPS_ME_SEE != I_MUST_NAME_TRACE
USEFUL_VOCABULARY != DUTY_TO_PROPAGATE_VOCABULARY
PARTICIPATION != EVANGELISM
FIELD_CONTACT != FRAMEWORK_ADOPTION
```

Prefer native mechanism questions in Square participation, e.g.:

- What evidence distinguishes zero results from a search that never completed?
- What observation would show that this decision changed the underlying mechanism?
- What could this witness actually observe?

Do not treat later native rediscovery as independent if TRACE vocabulary or conclusions were seeded into the same population/pathway.

Conversely, preserve native field evidence that predates the later TRACE/GLM framing. #1233 is important precisely because its rule-installation/firing language arose in the Square before this quarry named aperture actuation.

## 7. Falsification cases required before any integration

At minimum attack with paired cases where:

1. aperture available + deliberate non-use;
2. aperture available + default non-activation;
3. aperture nominally available but capability unavailable at use time;
4. external request triggers activation;
5. repeated passivity with causal mechanism UNKNOWN;
6. non-activation materially transfers burden;
7. non-activation does not transfer burden;
8. proactive activation itself creates burden/attention harm;
9. native field actor independently opens the same aperture without TRACE prompting;
10. TRACE-seeded field vocabulary later echoes back, demonstrating contamination risk.

A useful derived operator earns retention only if it distinguishes these cases more cleanly than existing selector + aperture + action/null-input + burden + evidence structure alone.

The #1233 field specimen should additionally be used as a transfer check: any candidate firing/actuation view must distinguish a rule that is absent, a rule that is recorded but not installed, a rule that is installed but whose trigger is not recognized, and a check that fires into an unsafe response handler.

The key frontier is:

> What causes an available aperture to be opened at all, and what evidence distinguishes deliberate non-activation from inherited/default/constraint-driven non-activation?

> What causes an already-represented rule/distinction/check to fire at the use-site where its consequence matters, and what happens after it fires?

Preserve the questions. Attack the mechanisms. Promote only what earns promotion.
